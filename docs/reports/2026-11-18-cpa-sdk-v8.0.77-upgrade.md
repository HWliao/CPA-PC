# CPA SDK v8.0.77 升级报告

核对日期：2026-11-18。CPA-PC 已将 CLIProxyAPI SDK 从 `v8.0.52` 升级到最新正式版 `v8.0.77`。本地测试和 Windows amd64 构建通过，但发现一项跨目录启动时的热重载路径冲突，以及两项上游 Windows 测试清理失败。

## 版本与依赖

| 项目 | 升级前 | 升级后 |
| --- | --- | --- |
| SDK | `github.com/router-for-me/CLIProxyAPI/v8 v8.0.52` | `v8.0.77` |
| 最低 Go 版本 | `1.26.10` | `1.26.10` |
| 实际验证工具链 | `go1.26.10 windows/amd64` | `go1.26.10 windows/amd64` |
| moego | `MoeForge/moego v0.1.0-alpha.1`，替换为 `router-for-me/moego v0.1.1` | `MoeForge/moego v0.1.0-alpha.4`，无替换 |
| bbolt | 无 | `go.etcd.io/bbolt v1.5.0`，本地间接依赖 |

GitHub Release 和 Go 模块查询均确认目标版本。发布时间为 `2026-11-17T22:18:44Z`，标签提交为 `a5e8f69e56309e1ef6d6872e667da81fdfbce2ce`。GitHub compare 返回 249 个提交，覆盖 `v8.0.53` 至 `v8.0.77` 的 25 个版本。

本地其余依赖版本没有变化。SDK 已移除旧 moego fork 的 `replace`，CPA-PC 同步删除这条过期规则。构建产物确认使用 `MoeForge/moego v0.1.0-alpha.4`。

## 主要升级内容

### 模型与协议转换

- 模型目录增加 GPT-6.2、GPT Image 2.6、Claude Fable 5.2、Gemini Omni 1.2 Flash 和 Gemini 4 系列条目，并更新 Devin 模型。实际可用性仍取决于凭证、供应商权限及目录配置。
- Codex 改进 Responses WebSocket 错误帧、429 和 `Retry-After` 传递、提前失败切换、未完成工具调用的会话修复，以及刷新结果不确定时的重复请求保护。
- Codex 增加兼容 Responses 上游的本地 compaction，修复 `max_output_tokens` 透传、小输出预算和远程 compaction v2。
- 图像请求可绕过 SIWC 直接使用 Codex Images 路径。Responses-Lite 对不支持的 hosted `image_generation` 请求改为明确拒绝。
- Claude、Gemini、Antigravity、OpenAI Chat 和 Responses 之间更完整地保留 thinking、工具结果、图片、音频、PDF 和文档块。修复 OpenAI Chat 到 Codex 的嵌套 `input_audio` 格式。
- Gemini 和 Antigravity 改进跨协议 thought signature 回放、零输出异常判定及 429 冷却时间识别。Devin 修复空完成切换、取消流被误报成功和 cache-write token 计数。

### OAuth、路由与会话

- 修复已禁用凭证、被拒绝的 refresh token 和过期检查时间导致的自动刷新循环。
- Codex/SIWC 改进 refresh token 轮换、续期窗口、刷新记录和原生 Codex 可用性。各内置供应商的定向重新登录更准确。
- 凭证列表增加 `oauth_provider`，登录流程支持显式 provider 提示并保留元数据。
- `routing.session-affinity-rebind-on` 增加 `never`，已建立的会话不再切换到其他凭证。
- weighted-round-robin 将粘性流量和固定凭证流量计入权重补偿，保持现有绑定。不同候选凭证集合分别记账，重启后积分重置。
- Claude Thread 保留所属凭证与 beta 配置。原凭证不可用时返回 `thread_not_found`，避免把线程交给其他账号。
- 请求自身造成的策略拒绝更准确地归为 400，避免误触发凭证冷却。Usage 增加 `request_scoped` 和 `force_cooldown` 失败分类。

### 配置与持久化

| 配置 | 新行为 |
| --- | --- |
| `server.kv-store` | 默认启用本地 bbolt，空路径使用 `<auth-dir>/kv.db`。`disabled: true` 使用内存模式。Home 模式使用 Home KV |
| `server.shutdown-timeout` | 默认 `0`，立即关闭。正值允许 HTTP 请求在预算内结束，WebSocket 由独立连接管理器关闭 |
| `requests.payload.replace` | 支持按最终上游角色、消息位置或 JSON 路径选择现有字符串，执行字面量和 Go RE2 正则替换，支持替换为空字符串 |
| `upstream.claude.server-side-fallback` | 默认 `false`，跨模型服务端回退改为显式启用。回退响应携带实际服务模型和回退元数据 |
| `upstream.claude.header-defaults.native-entrypoints` | 扩展原生 Claude Code 入口标识 |
| `sensitive-words-replace`、`sensitive-patterns-replace` | Claude、Antigravity 和 Devin 增加字面量及正则替换配置 |
| `oauth.providers.antigravity.tos-pause-window` | 可在 TOS 拒绝后暂停整个池，默认 `"0"`，不启用池级暂停 |

替换规则在 override 之后、filter 之前执行。角色基于协议转换后的最终上游请求，已合并到 system 的 developer 内容需要按 system 选择。路径规则只修改命中的现有字符串。

### 服务、管理与插件

- 新增 `/v1/tunnel`，提供按客户端 API key 隔离的 WebSocket 数据交换。没有配置或没有匹配的 `access.api-keys` 时拒绝连接。
- 新增 `/muse-code/models`、`/config`、`/search` 和 `/browser_open` 原生客户端接口。
- 新增 `GET /v8/management/observability/requests/in-flight`，查询在途请求数。
- 管理密钥 bcrypt 校验结果缓存一小时。本地集成测试确认更换密钥后，SDK 和 CPA-PC 路由均拒绝旧密钥、接受新密钥。
- SDK Builder 增加 executor wrapper、调用方 interceptor host 和配置应用回调，配置更新后保留调用方扩展。
- 插件增加可选 usage 归属、token 明细和 scheduler continuity hook，改进热重载、停用状态保留及凭证模型绑定。RPC schema 版本仍为 10。
- 错误日志区分本地错误与上游响应，减少成功响应体缓存，修复流错误和 WebSocket 日志归属。

## 冲突与风险

### 已复现：跨目录启动的热重载路径冲突

此项尚未修复，是本次升级最重要的部署风险。

触发条件是进程工作目录不同于 `config.yaml` 所在目录，并且 `oauth.auth-dir` 使用相对路径。CPA-PC 初始加载按配置目录解析，SDK watcher 热重载则直接使用相对路径。管理页面保存配置也会触发该流程。

诊断运行中，测试配置位于系统临时目录、工作目录为 `internal/app`。初始数据库位于测试配置的 `auth/kv.db`，修改管理密钥后出现以下路径变化：

```text
auth-dir: <临时配置目录>\auth -> auth
kv-store.path: <临时配置目录>\auth\kv.db -> auth\kv.db
```

随后在工作区 `internal/app/auth/kv.db` 发现新建文件。诊断产物已清理。

旧 SDK 的重载配置已有相对路径处理差异。新版新增 KV 配置应用，并让 watcher 更新实际认证目录及 fsnotify 监听，因此影响扩大到数据库位置和凭证目录监听。更换 KV 路径还会让此前的持久化状态暂时不可见。

`scripts/win/start-cpa-pc.vbs` 和计划任务把工作目录设为程序目录，配置也在同目录时通常不会触发。跨目录使用 `-config` 时，绝对 `oauth.auth-dir` 可避免这一问题。显式配置的相对 `server.kv-store.path` 同样以进程工作目录解析。

管理集成测试现在在自己的临时配置目录运行，匹配官方 Windows 启动方式，并避免测试向工作区写入 KV 文件。此项测试隔离不代表跨目录问题已修复。

### 默认 KV 持久化改变运行行为

- 升级后默认创建 `kv.db`，需要目录写权限。bbolt 文件不能由多个进程同时打开写入，打开锁等待预算为 5 秒。
- KV 打开失败时，SDK 记录错误但不阻止服务启动，也不自动转成内存模式。依赖 KV 的请求仍可能失败，健康检查成功不能证明 KV 可用。
- KV 启用后，Claude 会话日期固定值永久保存，`session-date-pin-days` 不再生效。关闭 KV 时才使用该内存保留时间。
- CPA-PC usage 继续使用原 SQLite 数据库，bbolt 是另一份 SDK 状态文件，本次没有 SQLite schema 迁移。

### 请求、路由和供应商行为变化

| 变化 | 影响 |
| --- | --- |
| Claude 服务端回退默认关闭 | 原先依赖自动跨模型回退的调用可能直接收到拒绝。显式开启后，实际模型与请求模型仍可能不同 |
| Claude 默认上游连接复用关闭 | 连接行为和握手开销变化，实际延迟需要真实供应商流量验证 |
| Antigravity `TOS_VIOLATION` | 命中凭证被停用。池级保护暂停默认关闭，显式设置正时长后才影响整个池 |
| `session-affinity-rebind-on: never` | 仅显式启用时生效，会话绑定凭证失效时降低故障切换能力 |
| 加权路由补偿 | 已使用 weighted-round-robin 的部署会看到新会话分配比例变化，现有会话保持绑定 |
| Responses-Lite hosted 图像校验 | 原本转发到上游的部分请求在本地返回 400，Images API 和显式 passthrough 有不同处理路径 |
| 请求级错误和零输出判定 | 部分错误状态、失败率、重试次数及凭证冷却统计变化 |
| 默认注册新接口 | `/v1/tunnel` 和 `/muse-code/*` 扩展可访问的服务能力，现有反向代理路径规则需要核对 |

### 上游 Windows 测试清理失败

完整执行 SDK `internal/kvstore` 测试时，以下两项在删除临时数据库时失败：

- `TestControllerPrioritizesHomeProviderOverLocalBoltStore`
- `TestControllerHelpersWithLocalBoltStore`

错误为 Windows 文件占用。`resetControllerForTest` 先注册 `ShutdownLocal` 清理，再创建 `t.TempDir()`，Go 按反序执行清理，导致临时目录先删除、数据库后关闭。失败发生在测试清理阶段，功能断言没有报告失败。

bbolt 基础操作、TTL、清理器、并发更新和本地 controller 生命周期的定向测试通过。CPA-PC 服务启动、关闭及临时目录清理也通过。上游 KV 全包结果仍记为失败，不能据此宣称上游测试全部通过。

### CPA-PC 集成结论

| 集成点 | 结论 |
| --- | --- |
| Builder、使用量插件、translator | 当前调用编译和测试通过，无需生产调用适配 |
| 管理路由 | 新路由没有占用 `/v8/management/cpa-pc/*`，SDK 和本地扩展可同时注册 |
| 管理密钥热更新 | 旧密钥失效、新密钥可用，覆盖新增在途请求接口 |
| 双文件配置 | 管理写入保留新增 SDK 字段，`cpa-pc.yaml` 内容不变，旧配置迁移保护测试通过 |
| Usage 新明细 | 新增 cached image/audio、HomeSelection 和失败分类不会自动写入 SQLite。`internal/usage/event.go` 仍显式选择本地支持字段，RawJSON 也由本地构造 |
| 本地费用统计 | 仍按本地 token 和价格计算，本次不具备新增图像、音频、工具明细的完整计费能力 |
| 管理前端 | 现有接口兼容。新开关、在途请求统计和登录元数据尚无本次专用 UI 适配 |
| Windows 单进程与静态页面 | 无 CGO 构建通过，静态页面继续由 SDK 路由提供 |

现有 v8 双文件配置没有新增的强制格式迁移要求。回退 SDK 时，新配置项、刷新后的凭证状态和 KV 状态需要一并核对，单独回退二进制不会撤销这些运行期变化。

## CPA-PC v2.0.2 发布校验

前后端版本号统一为 `2.0.2`，通过 `npm run package:windows -- --version 2.0.2 --build-frontend` 生成发布产物。

- Windows ZIP 为 `dist/cpa-pc_2.0.2_windows_amd64.zip`。
- 独立管理页面为 `static/management.html`，与 ZIP 内的页面字节一致。
- 包内程序 `-version` 返回 `cpa-pc 2.0.2`，构建元数据中的 SDK 为 `v8.0.77`。
- ZIP 的 CRC 校验通过，包含程序、双文件配置示例、管理页面、Windows 脚本、README 和 LICENSE。
- 前端 30 个测试文件中的 207 个测试通过，类型检查通过。

- 发布说明包含跨目录启动的相对认证路径风险，以及两项上游 Windows KV 测试清理失败。
