# CPA SDK v8.0.52 升级报告

核对日期：2026-11-03。CPA-PC 已从 CLIProxyAPI `v8.0.13` 升级到最新正式版 `v8.0.52`，本地验证通过。

## 版本与比对范围

| 项目 | 升级前 | 升级后 |
| --- | --- | --- |
| SDK 模块 | `github.com/router-for-me/CLIProxyAPI/v8 v8.0.13` | `v8.0.52` |
| 最低 Go 版本 | `1.26.0` | `1.26.10` |
| 本次验证工具链 | 默认工具链 `go1.26.3` | Go 自动选择 `go1.26.10` |
| SDK 版本回退常量 | `v8.0.13` | `v8.0.52` |

目标版本于 `2026-11-02T19:15:02Z` 发布，标签提交为 `6e6afab99a1939525ecb6bb1f0873c8e7a9df877`。GitHub Release 与 Go 模块查询均确认 `v8.0.52` 为最新正式版。

比对覆盖 `v8.0.14` 至 `v8.0.52`，共 39 个发布版本。GitHub compare 返回 519 个提交。两个版本的 Go 模块源码比对为 1,328 个文件变更，新增 206,303 行，删除 31,763 行。这些数字包含上游测试、文档和批量 JSON 库替换。

CPA-PC 的直接集成点是 `sdk/config`、`sdk/api`、`sdk/api/handlers`、`sdk/cliproxy`、`sdk/cliproxy/auth`、`sdk/cliproxy/usage` 和 `sdk/translator`。

### 模型、协议与供应商

| 范围 | 上游变化 | 对 CPA-PC 的影响 |
| --- | --- | --- |
| 模型目录 | 新增自定义 HTTP URL 或绝对文件路径目录源，支持动态重载、定时刷新和管理 API 主动刷新 | SDK 启动流程直接接入，可通过 `models.catalog`、`codex-catalog`、`devin-catalog` 配置 |
| 模型更新 | 增加 Gemini 3.8、Gemini 4 Argon、Claude Haiku 5.5、Muse Wonder 和 Grok Video 1.5 Lite 等定义，调整上下文与能力元数据 | 模型可见性仍由当前凭证、目录源和供应商权益共同决定 |
| Codex Responses | 支持 `response.interrupt`、更完整的 WebSocket 逐轮鉴权与错误处理，修复上游断连和早期 429 切换 | 改善长会话、并发工具调用和故障切换 |

| Gemini、Antigravity | 改进 thinking signature 回放、JSON Schema 清理、并行工具结果、媒体与文件附件、Interactions 会话续接 | 减少跨协议请求丢失信息和签名不匹配 |

### 配置、连接与路由

| 配置项 | 新增行为或默认值 |
| --- | --- |
| `server.max-request-body-bytes` | 限制请求体大小，超限返回 413。默认 `0`，不限制 |
| `server.response-compression.enabled` | 支持协商 gzip 和 zstd，包含 SSE，默认 `true` |
| `server.response-compression.min-bytes` | 非流响应默认从 1,024 字节开始压缩 |
| `server.github-token` | 配置全局 GitHub 请求 token，非空时优先于环境变量 |
| `requests.tls-handshake-timeout-seconds` | 限制共享 uTLS 客户端的握手时间，默认 `0`。不限制 TCP 建连、代理 CONNECT 或推理时长 |
| `requests.streaming.send-keepalive-before-ft` | 可在首 token 前发送 SSE 心跳，默认 `false` |
| `routing.session-affinity-rebind-on` | 默认 `any`。`quota` 模式使临时错误只切换当前请求，保留原会话绑定 |
| `api-keys` 下的 `connection-pool` | 按组配置、按 key 覆盖。省略时不启用，空映射也代表启用。连接池按 key 隔离 |
| `upstream.codex.upstream-request-compression` | 可对官方 ChatGPT Codex OAuth 请求使用 zstd，默认 `false`，400 或 415 后回退未压缩请求 |
| `upstream.codex.websocket-compression` | 协商 WebSocket permessage-deflate，默认 `true` |
| `upstream.claude.tool-search` | 启用 Codex 到 Claude 的工具搜索，默认 `false` |
| `upstream.claude.session-date-pin-days` | 会话日期固定默认保留 7 天，显式 `0` 使用原连续会话范围 |
| `client.codex.web-search-result-cache` | 会话搜索结果缓存默认关闭，默认 TTL 为 24 小时，上限为 1,024 |
| `client.claude.show-codex-commentary` | 可把 Codex 公共进度说明显示为 Claude 文本，默认 `false` |

连接池配置不作用于普通 OAuth 凭证。Antigravity 保留自己的开关，ChatGPT 浏览器指纹 transport 仍按每请求独立连接处理。

### 认证、管理与插件

- Codex 自动刷新提前量增加到 96 小时，修复刷新与认证文件保存并发覆盖、失效凭证反复刷新、重新登录后不能恢复轮转等问题。
- 新增 Sign in with ChatGPT 的绑定和状态接口，凭证列表增加续期、重新登录和恢复状态。
- OAuth 登录增加 POST 方式和会话级代理，可把代理设置保存到对应账号。
- v8 配置接口返回 `ETag`，可用 `If-Match` 检测并发修改。过期 token 返回 412。不带该头的旧客户端继续无条件写入。
- 增加凭证验证接口、模型目录主动刷新、按 channel 获取静态及插件模型定义。
- 插件 schema 从 6 增至 10，增加按阶段省略请求体、原始字节区间修改、多供应商模型、多 OAuth 登录入口和入口名称与图标。
- 修复插件跨 origin 重定向携带凭证头、模型执行流归属、并发卸载及同协议 SSE 转换问题。
- 修复请求日志路径遍历、日志注入、panic 后日志未完成、WebSocket 延迟日志持有请求内存等问题。

### Usage 与统计

SDK usage 增加 `SelectionID`、`IsNativeKey`、`AccessProvider` 和 `EffectiveServiceTier`。供应商 usage 明细还增加缓存创建时间档位、文本与图像及音视频 token、搜索次数、图像参数、工具调用、迭代和成本等结构化数据。

上游还修复 cached token、reasoning token、流中断和终止后取消的统计，以及异步处理读取复用 `gin.Context` 导致的身份串用。

## 破坏性改动与行为变化

### 明确的构建和源码破坏性改动

1. Go 最低版本提高到 `1.26.10`。关闭工具链自动下载且版本不足的构建环境会失败。发布二进制的使用者不需要安装 Go。
2. `translator.RequestTransform` 从 `func(...) []byte` 改为 `func(...) ([]byte, error)`。自行注册旧式请求转换回调的集成方需要改签名。CPA-PC 使用内置转换器与兼容的 `TranslateRequest`，当前调用不需要适配。
3. SDK 使用 `github.com/MoeForge/moego`，并把它替换为 `github.com/router-for-me/moego v0.1.1`。依赖模块的 `replace` 不会传递给主模块，CPA-PC 已在根 `go.mod` 明确采用同一替换，保证使用上游验证的代码版本。

### 影响部分现有部署的变化

| 变化 | 具体影响 |
| --- | --- |
| 内置模型目录删除旧模型 | `gemini-3.7-flash`、`gemini-3.6-flash-high`、`gemini-3.7-flash-high`、`gemini-pro-agent`、`gemini-3.1-pro-low` 不再出现在目标版内置通用目录。依赖旧 ID 的调用和别名需要核对。在线目录和自定义模型可能与内置目录不同 |
| Responses metadata 过滤 | 非 Codex 客户端不再接收部分私有 `response.metadata`。依赖这些内容的集成可能受影响 |
| 流完整性判定 | 缺少 finish reason 或终止帧的上游流可能被记录为 `stream_truncated` 失败，已有监控中的失败数量可能增加。已完成响应后的正常客户端断开则避免误记失败 |
| 响应压缩默认开启 | 声明接受 gzip 或 zstd 的客户端可能收到压缩内容，SSE 也在范围内。自定义客户端和中间代理需要正确处理 `Content-Encoding` |
| Codex 凭证选择 | 被识别为 Codex 客户端的请求忽略 `use_siwc`，使用外层非 SIWC 凭证。仅有有效 SIWC 分区、外层凭证失效时，该类请求可能失败 |
| Codex 自动续期 | 没有可用刷新凭据的 access-token-only 记录不再进入普通自动刷新队列。字段名需要是 `refresh_token`。终止性 grant 错误会提示在当前实例重新登录 |
| Claude `never` 或 `uncloak` | 非 CLI API-key 路径会移除传入的 Claude Code 身份与 billing 标记，已确认原生客户端的请求头处理也有调整 |
| OAuth excluded models 优先级 | 凭证自身非空的 `excluded_models` 优先，不与全局排除规则合并。自身未配置、空或 null 时继承全局规则 |
| mDNS 广播协议 | TXT 字段改为 AI gateway draft 格式，不再广播管理端点，`advertise-management` 废弃。读取旧 TXT 格式的发现客户端需要适配 |

插件 schema 的增加按版本和能力协商。旧插件不因 schema 数字变化就全部失效，但自定义插件可能受更严格的流归属、模型凭证绑定及回调规则影响。本次未验证实际安装的第三方动态库。

Amp 和 Gemini CLI 的删除发生在更早的升级中，不属于本次 `v8.0.13` 到 `v8.0.52` 的新增破坏性改动。

## 与 CPA-PC 的冲突及适配结论

| 集成点 | 结论与处理 |
| --- | --- |
| Go 工具链 | 原默认版本不足，已提高 `go.mod` 最低版本并使用 `go1.26.10` 完成验证 |
| moego 依赖替换 | 已复制 SDK 的版本限定 `replace`，构建产物元数据确认实际使用 fork `v0.1.1` |
| 服务构建和生命周期 | 现有 Builder、`WithServerOptions`、路由回调与停止流程通过测试，无需生产代码适配 |
| SDK 配置透传 | CPA-PC 从 SDK 加载完整配置后只覆盖自身负责的字段。新增字段在初始加载和管理写入后均保留 |
| 双文件配置与迁移 | `config.yaml` 仍归 SDK，`cpa-pc.yaml` 归 CPA-PC。已有迁移和旧单文件写保护测试通过 |
| 工作区已有迁移修改 | 开始时 `internal/app/migrate.go` 与 `migrate_test.go` 已有未提交修改，本次保留原内容，包含它们的测试在新 SDK 下通过 |
| 管理路由 | 上游新增路由不占用 `/v8/management/cpa-pc/*`。本地集成测试中的 SDK 和 CPA-PC 路由可同时注册，管理密钥热更新仍一致 |
| Usage 插件与 SQLite | `HandleUsage(context.Context, usage.Record)` 接口兼容，已有 token 和聚合字段继续落库。SQLite 无本次 schema 迁移 |
| 新 usage 字段 | `internal/usage/event.go` 显式挑选字段，`RawJSON` 也由本地重新构造。新增结构化明细不会自动落库，不能把 SDK 的新增统计能力视作 CPA-PC 页面已支持 |
| 本地费用计算 | 当前仍按本地 token 字段与模型价格计算。SDK 新增的图像、音频、工具、搜索与成本明细尚未进入本地计费逻辑 |
| 前端配置保存 | `web/src/services/api/configFile.ts` 不发送 `If-Match`，旧保存方式兼容，但还没有并发覆盖检测 |
| 前端新功能入口 | 当前 OAuth 调用和凭证文件请求仍兼容。SIWC、会话代理、凭证验证、多 OAuth 入口、目录刷新与新增配置项的专用 UI 需要单独对比上游前端后决定采纳范围 |
| 静态页面与 Windows | `/management.html` 仍由 SDK 提供。Windows amd64 且 `CGO_ENABLED=0` 的单进程构建通过 |

现有 v8 双文件部署没有新增的强制配置迁移要求。原有旧单文件迁移规则继续适用。回退到旧 SDK 时，旧版本不认识的新配置项及新凭证元数据需要一并复核。
